# Стенд сравнения бэкендов: CPU / OpenCL / CUDA / FPGA

Коротко: в проекте есть **одна задача деблюра и четыре её реализации**.
Приложение `deblur_bench` прогоняет их на одном кадре с одними
параметрами и печатает время и качество. Это позволяет сравнивать
бэкенды «яблоки с яблоками», не меняя алгоритм.

## Что такое деблюр в этом проекте

Смаз от движения убирается по каналу яркости (Y), цвет (хрома) остаётся
исходным:

1. Кадр переводится в YUV, берётся Y.
2. Y режется на блоки **256×256** с перекрытием: шаг 128, на выход идёт
   центральная часть 128×128 (у неё меньше краевых эффектов).
3. Для каждого блока по параметрам движения (`dx`, `dy`, `dalpha`,
   `exposure`) считается локальный вектор смаза `(L, θ)`.
4. Блок переводится в частотную область (2D FFT), умножается на
   винеровский фильтр `G(f) = H*(f) / (|H(f)|² + nsr)` и возвращается
   обратным FFT.
5. Результаты блоков собираются, к ним подмешивается исходная хрома.

Параметры движения задаются в пикселях (смещение за выдержку) и в
радианах (поворот вокруг центра кадра). `nsr` — уровень шума: меньше
значение → агрессивнее деблюр и больше ringing.

## Как устроен стенд

Общий интерфейс (`host/include/deblur/deblur.h`):

```cpp
deblur::MotionParams p;              // dx, dy, dalpha, exposure, nsr
auto eng = deblur::Engine::create(deblur::Backend::FPGA);
eng->process(src, dst, p);           // cv::Mat -> cv::Mat
```

Четыре реализации:

| Бэкенд | Что делает |
|:--|:--|
| `CPU` | эталон: OpenCV `cv::dft`, float, тот же блочный алгоритм |
| `OpenCL` | то же через `cv::UMat` и OpenCV T-API (GPU) |
| `CUDA` | то же через `cv::cuda::GpuMat` и `cv::cuda` (GPU) |
| `FPGA` | PCIe → XDMA → DDR3 → AXI DMA → 16 × xfft + ядро → обратно |

Схема FPGA-пути:

```
хост (C++/OpenCV)                        плата YPCB-00338-1P1
┌──────────────────┐   PCIe x4 Gen2   ┌────────────────────────────┐
│ Y-кадр, 32 бит   │ ───────────────► │ DDR3 → AXI DMA             │
│ параметры Q1.15  │                  │   → ядро Wiener (178 МГц)  │
│                  │ ◄─────────────── │     8 fwd + 8 inv xfft     │
└──────────────────┘                  │   → AXI DMA → DDR3         │
                                      └────────────────────────────┘
```

На хосте остаются только чтение/запись кадра, расчёт параметров
движения по блокам и смешивание с хромой. Сам деблюр целиком на плате.

## Как запускать

```bash
# все доступные бэкенды, 1080p, 7 замеров после 2 прогревочных
./host/build/deblur_bench --in blur.png --iters 7 --warmup 2 \
    --dx 9 --dy 0 --da 0 --exposure 1 --nsr 0.01

# только CPU и FPGA, с сохранением картинок
./host/build/deblur_bench --in blur.png --backends cpu,fpga \
    --dx 9 --dy 0 --exposure 1 --save /tmp/out

# список доступных бэкендов
./host/build/deblur_demo --list-backends
```

`blur.png` — это **уже смазанный** кадр; `--dx/--dy` описывают смаз,
который надо убрать. Быстрый тест можно сделать так:

```python
import cv2, numpy as np
img = cv2.imread("frame.png")
k = np.ones((1, 9), np.float32) / 9          # смаз 9 px по горизонтали
cv2.imwrite("blur.png", cv2.filter2D(img, -1, k,
            borderType=cv2.BORDER_REPLICATE))
```

## Что печатает стенд

```
backend     median ms       fps     vs CPU  note
------------------------------------------------
cpu             120.1      8.33      99.00  reference
opencl           89.2     11.21      95.62  PSNR dB
cuda            161.3      6.20      95.62  PSNR dB
fpga            113.7      8.79      45.65  PSNR dB
```

- **median ms** — медиана времени одного кадра. Медиана устойчивее
  среднего: случайный «тормоз» системы её не сдвигает.
- **fps** — сколько кадров в секунду, `1000 / median_ms`.
- **PSNR vs CPU** — насколько выход отличается от эталона CPU, в дБ.
  Больше = ближе. Для 8-битной картинки 40+ дБ means «на глаз не
  отличить»; 95 дБ — практически побитовое совпадение (обе реализации
  считают во float).
- **warmup** — первые прогоны не считаются: GPU и FPGA при первом
  вызове инициализируются, это не относится к установившейся скорости.

## Результаты (23.11.2026)

Хост: AMD Ryzen 7 5700X, GPU NVIDIA RTX 4070, плата XC7K480T
(ядро 178.57 МГц), OpenCV 5.0. Вход — синтетический кадр, смаз 9 px
по горизонтали, `dx=9, dy=0, exposure=1, nsr=0.01`.

### 1920×1080

| бэкенд | медиана, мс | fps | PSNR к CPU |
|:--|--:|--:|--:|
| CPU (эталон) | 121.6 | 8.2 | — |
| OpenCL (RTX 4070) | 93.6 | 10.7 | 95.6 дБ |
| CUDA (RTX 4070) | 175.4 | 5.7 | 95.6 дБ |
| FPGA (XC7K480T) | 94.5 | 10.6 | 45.7 дБ |

### 512×512

| бэкенд | медиана, мс | fps | PSNR к CPU |
|:--|--:|--:|--:|
| CPU (эталон) | 16.1 | 62.3 | — |
| OpenCL (RTX 4070) | 12.4 | 80.9 | 96.3 дБ |
| CUDA (RTX 4070) | 28.7 | 34.9 | 92.8 дБ |
| FPGA (XC7K480T) | 12.3 | 81.3 | 45.7 дБ |

## Как это понимать (важно)

1. **Это сравнение реализаций, а не теоретической мощности железа.**
   GPU-бэкенды — референсные: они делают много маленьких FFT 256×256
   и на каждый блок гоняют данные/коэффициенты между хостом и GPU.
   На таких размерах накладные расходы съедают выигрыш. Пакетная
   обработка или свои CUDA-ядра были бы заметно быстрее, но это
   отдельная оптимизация, которой в стенде пока нет.
2. **FPGA-время включает PCIe-обмен**: 8 МБ кадра в DDR3 и 8 МБ
   результата обратно (~11 мс суммарно при 1.5 ГБ/с). Это честное
   end-to-end время, как у остальных бэкендов.
3. **Разное качество — это разная арифметика.** CPU/OpenCL/CUDA
   считают во float (95 дБ — совпадение). FPGA считает в 24-битной
   фиксированной точке с Q1.15-параметрами и LUT-фильтром; 45.7 дБ
   соответствует ошибке ≈1.3 уровня яркости из 255. Визуально деблюр
   тот же, но для задач, где нужна побитовая идентичность float,
   FPGA-путь надо сравнивать именно с этим допуском.
4. **FPGA на 1080p немного быстрее CPU (≈1.3×) и на уровне OpenCL**.
   Ядро после ускорения 2026-11-23: strip разложен на 8 банков (загрузка
   блока идёт с II=1), проходы оставлены покадровыми (совмещённые
   send/recv ломают realtime-кадрирование xfft), хвост 1080p выдаёт
   строки по той же схеме, что и CPU. Дальше — 128-битный поток
   DMA/ядра и конвейер блоков.
5. **Малые кадры** (512×512) показывают, что при уменьшении работы
   накладные расходы начинают доминировать у всех: у GPU — запуск
   ядер, у FPGA — PCIe-транзакции, у CPU — сам алгоритм.

## Ограничения стенда

- Деблюр только по Y; хрома не обрабатывается (так задумано).
- FPGA-путь: `width ≤ 1920`, до 256 блоков параметров (1080p
  помещается; для 4K нужно расширение `params` и `W_MAX`).
- FPGA-параметры квантуются в Q1.15; `nsr` зашит в LUT (0.01), хост
  его не передаёт.
- GPU-бэкенды требуют сборки OpenCV с CUDA/OpenCL; при отсутствии
  устройства стенд честно печатает `unavailable`.

## Как добавить свой бэкенд

1. Унаследоваться от `deblur::Engine` и реализовать `process()`.
2. Зарегистрировать фабрику в `host/src/deblur.cpp`
   (`makeMyEngine()` + `available()`).
3. Добавить имя в `parse_backend()` в `deblur_bench.cpp`.

Стенд сам покажет время и PSNR относительно CPU — менять его не нужно.

## Словарик

- **Бэкенд** — конкретная реализация одного и того же алгоритма
  (CPU, GPU через OpenCL, GPU через CUDA, ПЛИС).
- **PSNR** — пиковое отношение сигнал/шум, мера отличия двух картинок
  в дБ. Чем больше, тем ближе результат к эталону.
- **fps** — кадров в секунду.
- **Warm-up** — прогревочные запуски, чтобы в измерение не попали
  инициализация контекста, компиляция ядер и прогрев кэшей.
- **FPGA/ПЛИС** — программируемая логика; здесь на ней собран
  потоковый FFT-конвейер, а не выполняется софт.
