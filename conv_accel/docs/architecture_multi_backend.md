# Архитектура: единый C++/OpenCV проект с бэкендами OpenCL / CUDA / FPGA

Цель: одно приложение на C++/OpenCV, которое вызывает одну и ту же
деконволюцию через `OpenCL GPU`, `CUDA GPU` или `FPGA`, выбирая бэкенд
на старте. FPGA-бэкенд — плата YPCB-00338-1P1 (Kintex-7 XC7K480T,
PCIe x4 Gen2, DDR3).

## API

`host/include/deblur/deblur.h`:

```cpp
deblur::MotionParams p;      // dx, dy, dalpha, exposure, nsr, block, hop
auto eng = deblur::Engine::create(deblur::Backend::FPGA);
eng->process(src, dst, p);   // cv::Mat / cv::UMat
```

Бэкенды:

| Backend | Реализация |
|:--|:--|
| `CPU` | эталон на хосте (та же блочная схема, для проверки) |
| `OpenCL` | `cv::UMat`, `cv::dft`/`mulSpectrums` или свои ядра |
| `CUDA` | `cv::cuda::GpuMat`, `cv::cuda::dft` или свои ядра |
| `FPGA` | PCIe → AXI DMA → DDR3, блочный FFT-винер на плате |

`Backend::Auto` выбирает первый доступный (FPGA → CUDA → OpenCL → CPU).

## Что уже измерено по FPGA

### FFT-ядро: 24 бита, `unscaled`, `realtime`

| вариант | DSP | BRAM18 | LUT | FF | поток |
|:--|--:|--:|--:|--:|:--|
| `hls::fft` fp32, `nonrealtime` | 34 | 7 | 11 645 | 14 625 | 0.31 отсч./такт |
| `xfft` 16 бит, `realtime`, scaled | 12 | 4 | 2 511 | 4 530 | 1 отсч./такт |
| `xfft` 24 бита, `realtime`, `unscaled` | **18** | **4** | 2 927 | 5 339 | **1 отсч./такт** |

8 ядер 24-бит: **144 DSP (7.5 %), 32 BRAM18 (1.7 %)**.

Почему 24 бита: 16-битный промежуточный спектр (между строками и
столбцами) теряет мелкие бины — round-trip 22.7 дБ. 24-битный даёт
**70.8 дБ**, а винер — **52.2 дБ** против float-эталона (max|err| 7e-5).

Realtime включается приватной копией `hls_fft.h` с
`throttle_scheme=realtime` (генерируется в `build.tcl`); fixed-point API
`hls::fft<config>` с `ap_fixed<24,1>` работает как есть.

### Сколько ядер нужно

Стоимость блочного 2D-FFT на выходной пиксель:

```
2 прохода (строки + столбцы) × 2 (FFT + IFFT) × 4 (перекрытие 50%) = 16 отсчётов/пиксель
```

| режим | пикселей/с | отсчётов/с | ядер по 250 МГц |
|:--|--:|--:|--:|
| 1080p30 | 62.2 M | 0.99 G | **4** |
| 1080p60 | 124.4 M | 1.99 G | **8** |

8 ядер 24-бит: **144 DSP (7.5 %), 32 BRAM18 (1.7 %)**. Дёшево.

**Измеренная пропускная способность (важно).** В синтезе row-pass
каждое ядро даёт **878 тактов на 256-точечный FFT = 3.4 такта/отсчёт**,
а не 1. Обёртка `hls::fft` сливает pipeline между вызовами (на каждый
вызов — свой config/status). Загрузка/выгрузка при этом идут по
8 отсчётов/такт, т.е. память не узкое место.

Следствие: 8 ядер = **2.35 отсчёта/такт** → ~20 fps, не 60.

Варианты:
1. **Прямой `xfft` IP в BD** с непрерывным AXI-Stream и `tlast` каждые
   N отсчётов (без перезаписи config на кадр) — целевое 1 такт/отсчёт,
   тогда 8 ядер достаточно.
2. **~27 ядер** при текущей обёртке: 27 × 18 = 486 DSP (25 %),
   ~108 BRAM18 (5.6 %) — влезает, но управление 27 потоками сложнее.

### Где реальная стоимость — память

Текущий проект уже занимает **172.5 / 955 RAMB36 (18 %)**. Рабочий
блок — **256×256, hop 128**. При перекрытии 50 % стоимость на пиксель
не зависит от размера блока (16 отсчётов/пиксель), а 256 даёт **лучший
PSNR**, чем 512:

| D | размыто | B512 / h256 | B256 / h128 |
|--:|--:|--:|--:|
| 0.2 | 21.61 | 28.21 | **30.01** |
| 0.5 | 19.31 | 23.94 | **24.88** |

Буфер 256×256 комплексных Q17.15 (`unscaled` FFT, 32 бита) = 512 КБ =
~114 RAMB36 (12 %). Два буфера = **24 %**, плюс 8 FFT-ядер и таблицы —
итого **~37 %** вместе с текущим проектом. Запас большой.

Почему `unscaled`, а не 16-битный BFP: у обратного FFT промежуточный
рост `N²` уводит изображение ниже LSB 16 бит (проверено в csim —
картинка разрушается). `unscaled` даёт 16-битный вход и 25-битный выход
(Q17.15); изображение сохраняется, а блок-нормализация спектра перед
обратным FFT использует все 16 бит.

Буферы раскладываются по плиткам 8×8:

```
buf[c/8][r/8][c%8][r%8]
#pragma HLS array_partition variable=buf complete dim=3
#pragma HLS array_partition variable=buf complete dim=4
```

Тогда и запись транспонирования (8 строк в один столбец), и чтение
8 столбцов идут по 8 разным банкам — 8 отсчётов/такт без конфликтов.

### PSF: отрезок вместо дуги

Точная локальная PSF — дуга. Проверка на `D=0.5` (тот же стенд):

| PSF на блок | всё | центр | 400–700 | углы |
|:--|--:|--:|--:|--:|
| точная дуга | 23.94 | 27.32 | 25.02 | 21.01 |
| отрезок (`L`, `θ` в центре блока) | 24.02 | 27.29 | 25.07 | 21.12 |
| **аналитическая sinc-OTF** | **24.05** | 27.52 | 25.08 | 21.14 |

То есть достаточно двух чисел на блок:

```
s = T + (R(Φ) − I)(r0),   L = |s|,   θ = atan2(sy, sx)
a = (L/B)(kx cosθ + ky sinθ)
H = exp(−iπa)·sinc(πa)
G = conj(H)/(|H|² + nsr)
```

`G` нельзя считать через `double sin/cos`: синтез даёт **3327 DSP
(173 %)**. Нужна LUT: хост считает 8–16k значений `G(a)` (Q1.15) для
текущих `nsr, gs` и загружает в BRAM; ядро делает
`a = (L/B)(kx cosθ + ky sinθ)` → индекс → `G`.

## Поток данных FPGA

```
host: cv::Mat
  └─ AXI DMA → DDR3 (входной кадр)
       └─ kernel (m_axi):
            для каждого блока 256×256 с перекрытием:
              load → 2D FFT (строки → транспонирование → столбцы)
              → G = conj(H)/(|H|²+nsr)   (PSF в центре блока)
              → 2D IFFT → окно/накопление
            → DDR3 (выходной кадр)
  └─ AXI DMA → cv::Mat
```

Параметры `(dx, dy, dalpha, exposure, nsr)` — в AXI-Lite регистрах.
PSF на блок — отрезок `(L, θ)` из траектории; `G` — аналитический
`sinc`-OTF (см. выше), без буфера под PSF.

## Этапы

1. **csim 2D FFT 64×64** — сделан: max|err| 4e-5, структура
   строки → транспонирование → столбцы верна.
2. **csim блока 128×128, 8 ядер, float** — сделан: **131.3 дБ** против
   CPU. Структура FFT → G → IFFT и плиточное транспонирование верны.
3. **csim 128×128, 8 ядер, 24 бита `unscaled`** — сделан: round-trip
   **70.8 дБ**, винер **52.2 дБ** против float.
4. **LUT для `G`** — сделан: **51.3 дБ**, DSP в синтезе 3327 → 672.
5. **Синтез 256×256, 8 ядер** — сделан: ядра параллельны (144 DSP,
   Fmax 324 МГц), но **3.4 такта/отсчёт** на ядро → ~20 fps.
6. **Прямой `xfft` IP** — подтверждён **1 такт/отсчёт** (512 отсчётов
   за 512 тактов, кадры вплотную). Обёртка была виновата.
7. **HLS-ядро с 32 AXI-Stream портами** (8 fwd + 8 inv) — синтез:
   BRAM 30 %, DSP 20 %, Fmax 255 МГц. Латентность блока 156k тактов,
   из них FFT-конвейер 26k (~14 мс/кадр), остальное — поток пикселей
   по 1/такту.
8. **Strip/frame контроллер (Y-only)**: чтение кадра один раз в
   strip-буфер, блочный конвейер — убрать 4-кратное чтение и
   перекрыть I/O с FFT. Цель 60 fps.
9. **BD**: 16 xfft IP + ядро + AXI DMA; хост `deblur::Engine`.
10. **OpenCL/CUDA бэкенды** за тем же `deblur::Engine`.
