# Архитектура: единый C++/OpenCV проект с бэкендами OpenCL / CUDA / FPGA

Цель: одно приложение на C++/OpenCV, которое вызывает одну и ту же
деконволюцию через `OpenCL GPU`, `CUDA GPU` или `FPGA`, выбирая бэкенд
на старте. FPGA-бэкенд — плата YPCB-00338-1P1 (Kintex-7 XC7K480T,
PCIe x4 Gen2, DDR3).

## API

`host/include/deblur/deblur.h`:

```cpp
deblur::MotionParams p;      // dx, dy, dalpha, exposure, nsr, block, hop
auto eng = deblur::Engine::create(deblur::Backend::FPGA);
eng->process(src, dst, p);   // cv::Mat / cv::UMat
```

Бэкенды:

| Backend | Реализация |
|:--|:--|
| `CPU` | эталон на хосте (та же блочная схема, для проверки) |
| `OpenCL` | `cv::UMat`, `cv::dft`/`mulSpectrums` или свои ядра |
| `CUDA` | `cv::cuda::GpuMat`, `cv::cuda::dft` или свои ядра |
| `FPGA` | PCIe → AXI DMA → DDR3, блочный FFT-винер на плате |

`Backend::Auto` выбирает первый доступный (FPGA → CUDA → OpenCL → CPU).

## Что уже измерено по FPGA

### FFT-ядро 512 точек, 16 бит fixed-point

| вариант | DSP | BRAM18 | LUT | FF | поток |
|:--|--:|--:|--:|--:|:--|
| `hls::fft` (обёртка, fp32, `nonrealtime`) | 34 | 7 | 11 645 | 14 625 | 1657 тактов / 512 = 0.31 отcч./такт |
| `xfft` IP (`realtime`, 16 бит) | **12** | **4** | 2 511 | 4 530 | **1 отcч./такт** |

Частота: OOC-синтез с ограничением 100 МГц дал WNS +7.843 нс, то есть
критический путь ~2.16 нс (≈460 МГц). На 250 МГц запас большой.

Вывод: **HLS-обёртка `hls::fft` не годится для 60 fps** — она в 3.2 раза
медленнее. Нужен `xfft` IP в режиме `realtime`. Он включается приватной
копией `hls_fft.h` с `throttle_scheme=realtime` (генерируется в
`build.tcl`); публичный fixed-point API `hls::fft<config>` с
`complex<ap_fixed<16,1>>` работает без изменений.

Точность 16-битного FFT (csim, 512 точек, Q1.15):

| режим | SNR | масштаб |
|:--|--:|:--|
| фиксированный 1/512 | 58.8 дБ | без переполнения |
| **block floating point** | **74.1 дБ** | экспонента блока 7, восстанавливается точно |

Поэтому в ядре — BFP: экспонента каждого 1D-преобразования нормализуется
к общему масштабу сдвигом `E_ref − E_row` (только вправо, без
переполнения) перед винеровским умножением.

### Сколько ядер нужно

Стоимость блочного 2D-FFT на выходной пиксель:

```
2 прохода (строки + столбцы) × 2 (FFT + IFFT) × 4 (перекрытие 50%) = 16 отсчётов/пиксель
```

| режим | пикселей/с | отсчётов/с | ядер по 250 МГц |
|:--|--:|--:|--:|
| 1080p30 | 62.2 M | 0.99 G | **4** |
| 1080p60 | 124.4 M | 1.99 G | **8** |

8 ядер: **96 DSP (5 %), 32 BRAM18 (1.7 %), ~20k LUT, ~36k FF**. Дёшево.

### Где реальная стоимость — память

Текущий проект уже занимает **172.5 / 955 RAMB36 (18 %)**. Блок
512×512 комплексных 16-бит = 1 МБ = ~228 RAMB36 (24 %). Два буфера
(row-major + column-major) = **~48 %**, плюс 8 FFT-ядер (32 BRAM18 =
1.7 %) и служебные таблицы. Итого **~67 %** — влезает с запасом ~30 %.

Буферы раскладываются по плиткам 8×8:

```
buf[c/8][r/8][c%8][r%8]
#pragma HLS array_partition variable=buf complete dim=3
#pragma HLS array_partition variable=buf complete dim=4
```

Тогда и запись транспонирования (8 строк в один столбец), и чтение
8 столбцов идут по 8 разным банкам — 8 отсчётов/такт без конфликтов.
Блок 256 не нужен: при перекрытии 50 % стоимость на пиксель не зависит
от размера блока (16 отсчётов/пиксель), а 512 даёт лучший PSNR.

### PSF: отрезок вместо дуги

Точная локальная PSF — дуга. Проверка на `D=0.5` (тот же стенд):

| PSF на блок | всё | центр | 400–700 | углы |
|:--|--:|--:|--:|--:|
| точная дуга | 23.94 | 27.32 | 25.02 | 21.01 |
| отрезок (`L`, `θ` в центре блока) | 24.02 | 27.29 | 25.07 | 21.12 |
| **аналитическая sinc-OTF** | **24.05** | 27.52 | 25.08 | 21.14 |

То есть достаточно двух чисел на блок:

```
s = T + (R(Φ) − I)(r0),   L = |s|,   θ = atan2(sy, sx)
a = (L/B)(kx cosθ + ky sinθ)
H = exp(−iπa)·sinc(πa)
G = conj(H)/(|H|² + nsr)
```

`G` считается на лету по LUT для `sinc` (2 умножителя + сумма + LUT);
буфер 1 МБ под `G` и FFT от PSF не нужны.

## Поток данных FPGA

```
host: cv::Mat
  └─ AXI DMA → DDR3 (входной кадр)
       └─ kernel (m_axi):
            для каждого блока 512×512 с перекрытием:
              load → 2D FFT (строки → транспонирование → столбцы)
              → G = conj(H)/(|H|²+nsr)   (PSF в центре блока)
              → 2D IFFT → окно/накопление
            → DDR3 (выходной кадр)
  └─ AXI DMA → cv::Mat
```

Параметры `(dx, dy, dalpha, exposure, nsr)` — в AXI-Lite регистрах.
PSF на блок — отрезок `(L, θ)` из траектории; `G` — аналитический
`sinc`-OTF (см. выше), без буфера под PSF.

## Этапы

1. **csim 2D FFT 64×64** — сделан: max|err| 4e-5, структура
   строки → транспонирование → столбцы верна.
2. **csim блока 512×512, 8 ядер**: BFP + аналитический `G` + IFFT против
   Python-эталона. Критерий: PSNR в пределах 0.5 дБ.
3. **Один блок на железе**: 8 ядер `xfft` realtime, замер такта.
4. **Полный кадр, 8 ядер (1080p60)**: AXI DMA + m_axi + WOLA.
5. **OpenCL/CUDA бэкенды** за тем же `deblur::Engine`; сравнение PSNR и
   скорости на одном кадре.
