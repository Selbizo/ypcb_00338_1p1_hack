# Эталонный тест винеровской деконволюции

Дата: 2026-11-16. Синтетическая сцена 1920×1080 (текст, фигуры, zone plate,
шум σ≈8), точный рендер смаза по траектории и блочная винеровская
деконволюция с локальной PSF. Скрипты: `/tmp/opencode/gt/gt3a.py`,
`gt3e.py` (в репозиторий не входят).

## Модель смаза

Для точки `p` кадра и нормированного времени выдержки `u ∈ [0,1]`:

```
p(u) = c + u·T + R(u·Φ)·(p − c)
T = D·(dx, dy),   Φ = D·dα,   c — центр кадра
```

PSF в точке `p` — это распределение смещений `s(u) = p(u) − p`, то есть
дуга/отрезок, а не одна глобальная PSF. Для блока она считается в его
центре; для `Φ=0` это обычная линия длины `|T|`.

## Найденная ошибка (важно для воспроизводимости)

OpenCV `warpAffine` по умолчанию считает `dst(x) = src(M⁻¹x)`. В первой
версии в `M` передавалась обратная матрица, поэтому рендер размытия шёл
в противоположную сторону, а PSF — в прямую. Из-за этого модель не
совпадала с рендером (23.6 дБ вместо точного совпадения), и деконволюция
делала картинку хуже.

После передачи `M = W_u` (прямая матрица):

| проверка | PSNR модель vs рендер |
|:--|--:|
| чистый сдвиг 5 px | **153 дБ** |
| сдвиг 15.8 px, патч 256 | **142 дБ** |
| сдвиг+вращение, патч 256 | 37–44 дБ |

Остаток при вращении — это не ошибка, а изменение PSF внутри патча
256 px (PSF зависит от координаты). На блоке 128–256 px он мал.

## Результаты: PSNR к резкому эталону

Размытие полное (сдвиг + вращение), `dx=30`, `dy=10`, `dα=0.1`.
Деконволюция: блок 512, hop 256, окно Ханна на выходе (WOLA), `nsr=1e-2`.
«Сдвиг» — деконволюция с PSF только по `T` (вращение игнорируется).

| D | макс. смаз (угол) | размыто | PSF сдвиг | **PSF сдвиг+вращ** | центр | 400–700 | углы |
|--:|--:|--:|--:|--:|--:|--:|--:|
| 0.1 | 12 px | 23.67 | 22.95 | **33.35** | 37.90 | 33.53 | 31.24 |
| 0.2 | 24 px | 21.61 | 20.59 | **28.21** | 32.35 | 29.45 | 25.16 |
| 0.3 | 36 px | 20.54 | 19.44 | **26.34** | 29.71 | 27.59 | 23.38 |
| 0.5 | 60 px | 19.31 | 18.28 | **23.94** | 27.32 | 25.01 | 21.01 |

## Выводы

1. **Вращение обязательно.** Деконволюция только по сдвигу *хуже*
   исходного размытого кадра на всех `D`: модель PSF неверна, и фильтр
   вносит больше ошибки, чем убирает. Учёт `dα` даёт +4.6…+9.7 дБ.
2. **Локальная PSF работает.** Для типичного `D=0.2` (смаз 6–24 px)
   восстановление 28.2 дБ против 21.6 у размытого; визуально текст и
   фигуры читаются, остаётся умеренный звон.
3. **Предел — длина смаза.** При `D=0.5` (до 60 px на угле) центр ещё
   восстанавливается (27.3 дБ), но на углах остаётся «двоение»: часть
   информации в нулях OTF потеряна безвозвратно.
4. **Блочная схема достаточна.** Блок 512 / hop 256 с окном на выходе
   убирает швы. Блок 256 хуже (круговой нахлёст обратного фильтра),
   блок 1024 не даёт выигрыша. `nsr≈1e-2` — хорошая точка для этого
   уровня шума; на периферии регуляризацию можно увеличивать.
5. **Для железа** PSF на блок считается аналитически из `(dx,dy,dα)`;
   это почти бесплатно по сравнению с FFT. Основная стоимость — блочный
   2D-FFT; при блоке 512 и перекрытии 50 % для 1080p60 нужно несколько
   параллельных FFT-ядер.
